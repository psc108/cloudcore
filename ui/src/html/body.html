Capacity

        
      

      

        Current load on this host and every paired peer, side by side — which one's actually overloaded, and which
        can tolerate placing another resource on it. CPU load is the 1-minute load average normalized by core
        count (a load of 1.0 on 4 cores shows as 25%, so it stays comparable across hosts with different core
        counts); Memory and Disk are the standard "how full is it" percentages. Placement is the worst of the
        three, in one glance — 🟢 use for resources, 🟡 risky but could try, 🔴 leave alone.

Settings

        
      

      

        Platform-wide settings, applied to every build going forward — existing builds are unaffected.
      


      
OpenTofu

      

        

          
          
          Max concurrent resource operations per tofu apply/destroy. Lower this on a host with limited CPU/RAM running a large template with many instances — a high default can starve slower-booting nodes' own dependency waits (e.g. a database node's own dependents timing out waiting for it). Leave blank for OpenTofu's own default (10).
        

      


      
Networking — Cross-Host Peering

      

        

          
          Off by default. Only when this is on does this host broadcast its presence (hostname + pairing fingerprint, nothing else) so other CloudCore hosts can find it under Peers → Discover & Pair — and only then is the peer-facing port even open at all. Turning this off closes it again and stops all broadcasting immediately, no restart needed. A host can still be paired-with by address even while this is off (see Peers → Pair Manually) — this setting only controls whether it announces itself.
          Announcing yourself only makes you findable — a peer that pairs with this host still can't actually place a worker, coordinator, or anything else here until this host has its own VPC, subnet, and security group ready to receive it. That's what "Create infrastructure" below is for.
          

        

        

          
          
          This host's guest VMs live on 192.168.<octet>.0/24. Two hosts you intend to pair must use different octets, or cross-host routing is ambiguous. Changing this only updates what this setting records — it does not itself move the live bridge; re-run sudo bash api/setup-network.sh <octet> afterward to actually apply it (see the README).
